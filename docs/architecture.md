# Academia Shield System Architecture & Security Specification

## 1. Overview
**Academia Shield** is a secure, institutional-grade classroom endpoint governance platform designed for schools, universities, and exam centers. It enables faculty members to temporarily restrict distractions (unauthorized websites, games/chat applications, and removable mass-storage devices) during class sessions and exams while preserving student privacy and preventing system lockouts.

## 4. Security & Safety Model

### 1. Zero-Stealth & Visible Student Consent
- The student endpoint agent **never operates invisibly or secretly**.
- When an active session is in progress, the student interface clearly displays:
  - Active Session title & instructor name
  - Expiry countdown timer
  - Exact list of blocked domains and application executable names
  - A 1-click **"Request Assistance / Unlock"** channel to the professor.

### 2. Fail-Safe Auto-Restoration Watchdog
- If the student machine loses network connection with the Academia Shield backend for longer than the institutional grace period (default: **120 seconds**), the agent triggers its fail-safe auto-unblock routine:
  - Restores `hosts` file to clean state
  - Restores default network DNS settings
  - Restores normal USB mass storage read/write permissions
  - Deactivates process termination logic.

### 3. Non-Destructive USB Mass-Storage Policy
- When USB restriction is enabled for an active exam session, the agent applies Windows Removable Storage Policy (`HKLM\SOFTWARE\Policies\Microsoft\Windows\RemovableStorageDevices\Deny_All = 1`).
- **Essential input peripherals (USB Keyboards, Mice, Webcams, Headsets) are NEVER restricted or interfered with.**

### 4. Cryptographic Policy Verification (Ed25519)
- Policy bundles generated by the backend authority are signed with an institutional private key.
- The student agent validates the cryptographic signature using the embedded public key before applying any restrictions.
